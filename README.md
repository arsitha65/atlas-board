# Atlas — Kanban Task Manager

Atlas is a responsive Kanban board for organizing tasks in a private guest workspace.

- **Live demo:** https://atlas-board-tau.vercel.app
- **GitHub:** https://github.com/arsitha65/atlas-board

## Technology stack

- React and TypeScript for the frontend
- Vite for development and production builds
- Supabase Auth for anonymous guest sessions
- Supabase Postgres for data storage and Row Level Security (RLS)
- dnd-kit for pointer and keyboard drag-and-drop
- Lucide React for icons
- Vercel for frontend hosting

The frontend calls Supabase directly. No separate backend server is required.

## Features

- Four columns: **To Do**, **In Progress**, **In Review**, and **Done**
- Create, edit, and delete tasks
- Drag tasks between columns to update their status
- Automatic anonymous sign-in and a private task board for each guest
- Task descriptions, priorities, and optional due dates
- Team member profiles with names, colors, and initials
- Multiple assignees and labels per task
- Chronological comments and server-generated activity history
- Title search and filters for priority, assignee, and label
- Due-soon and overdue indicators
- Total, completed, and overdue counts, plus completion percentage
- Responsive layout, empty states, loading indicators, and error messages

Team members are profiles within a guest's workspace, not invited accounts. Data persists in Supabase; access to a guest workspace depends on retaining that browser's session.

## Run locally

### 1. Prerequisites

Install Node.js 22.12+ or Node.js 24 LTS, npm, and Git. You also need a free Supabase project.

### 2. Clone and install

```bash
git clone https://github.com/arsitha65/atlas-board.git
cd atlas-board
npm ci
```

### 3. Configure Supabase

1. Create a free Supabase project.
2. Enable **Anonymous Sign-Ins** in the project's Authentication settings.
3. Open the Supabase SQL Editor.
4. Run the entire contents of `supabase/schema.sql` once in a fresh project. This creates the tables, constraints, indexes, triggers, and RLS policies.
5. Copy the project's URL and public anon key from the project settings. A modern publishable key also works with this client.

### 4. Configure environment variables

Copy the example file:

```bash
cp .env.example .env
```

Edit `.env` with your own public values:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Never use a Supabase service-role key, secret key, or database password in this frontend. `.env` is excluded from Git.

### 5. Start the app

```bash
npm run dev
```

Open the local URL printed in Terminal. Restart the development server after changing `.env`.

If Supabase is not configured, the app offers a clearly marked local preview. Preview changes are temporary and do not use the database.

## Production build

```bash
npm run build
npm run preview
```

The production build is generated in `dist`. The preview command serves that build locally.

## Deploy to Vercel

1. Import this GitHub repository into Vercel.
2. Select the **Vite** framework preset.
3. Set the build command to `npm run build` and output directory to `dist`.
4. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` using the project's public values.
5. Deploy. If environment variables change, redeploy to rebuild the frontend.

## Using the board

Click **New task** or a column's plus button to create a task. Click a task title to edit it or view comments and activity. Use the drag handle to move a card between columns, or change its Status dropdown in the editor.

For keyboard dragging, focus the handle, press Space, use the arrow keys, and press Space again to drop. Escape cancels dragging. On smaller screens, scroll horizontally to reach the other columns.

Create members and labels from the sidebar, then select them in the task editor. Search matches task titles without case sensitivity. Filters combine with AND; summary statistics describe the full board.

A task is overdue when its due date is earlier than the browser's local calendar date. Today through two days ahead is considered due soon. Completed tasks are excluded from overdue indicators.

## Database and security

The full database definition is in `supabase/schema.sql`.

| Table | Purpose |
|---|---|
| `tasks` | Task content, status, priority, due date, assignments, and owner |
| `team_members` | Guest-owned member profiles |
| `labels` | Guest-owned labels |
| `comments` | Comments linked to tasks |
| `task_activity` | Server-generated task history |

Each table has RLS enabled. Policies scope access to the current guest's `auth.uid()`. Task validation prevents foreign member/label assignments and changes to task ownership. Comment inserts must reference a task owned by the same guest. Audit records are generated by a database trigger and cannot be written directly by frontend users.

The public browser key identifies the Supabase project; RLS controls access to the data. Task updates use `updated_at` to detect stale edits from another tab. Failed saves display an error rather than claiming success.

## Project structure

```text
src/
  App.tsx          Board, task editor, team members, labels, comments, activity
  api.ts           Supabase authentication and database requests
  domain.ts        Types, filtering, and due-date rules
  main.tsx         React entry point
  styles.css       Styling and responsive layout
supabase/
  schema.sql       Full database setup
tests/             Domain tests and an opt-in RLS integration script
.env.example       Public environment variable template
```

## Tradeoffs

- The app saves on drop; other tabs require a manual refresh rather than realtime subscriptions.
- Card order follows creation order within each column; arbitrary reordering is not implemented.
- Member and label catalogs support creation, not editing or deletion.
- Multiple assignments use bounded UUID arrays validated by database triggers.
- Comments are append-only, and deleting a task also deletes its comments and activity.
- Clearing browser storage loses access to the anonymous workspace; account recovery is not implemented.
- Offline queuing and pagination are not implemented.

Future improvements include recoverable accounts, realtime updates, normalized assignment tables, pagination, and stronger abuse protection for anonymous sign-ups.
